Logging

open class Logging

Created by selwynleeke on 2015-05-15. Logging should follow the following rules: 1. Initial setup of the SDK and anything that may prevent a major function of the SDK should always be output using Logging.alwaysLog 2. Anything that could be useful to help the client debug an issue should use Logging.log 3. Anything that should only be seen internally should use the Logging.expLog function 4. The logging levels should be used as follows: VERBOSE: For the overly-frequent messages which could be useful sometimes, but are mostly just annoying DEBUG: For showing events used specifically to debug certain scenarios (not shown in QA builds) INFO: General day-to-day running of the app - stuff that happens a lot WARN: Non-fatal errors ERROR: Errors that might cause problems
